    A Symmetric-Key Encapsulation Profile with Initiator Auxiliary
                  draft-famed-sk-pmd-v03-00


Abstract

   This document specifies a one-message symmetric-key encapsulation
   profile in which the initiator computes a unary auxiliary value
   aux(sec) at the time the ciphertext is assembled.  The
   auxiliary value is local to the initiator and does not appear
   on the wire.

1.  Introduction

   This profile follows the structure of the base symmetric-key
   encapsulation.  The initiator additionally evaluates a unary
   function aux applied to the freshly drawn secret payload; the
   resulting value is intended for initiator-local bookkeeping
   such as audit logging or rate observation.

2.  Terminology

   The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL
   NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED",
   "MAY", and "OPTIONAL" in this document are to be interpreted as
   described in BCP 14 [RFC2119] [RFC8174].

      aux(x)    a unary function whose only operational use is to
                produce an initiator-local auxiliary value.

3.  Protocol Overview

      Initiator (I)                                       Responder (R)
         |                                                     |
         |   1.  senc(<sec, pub>, k)                           |
         |---------------------------------------------------->|
         |                          (release of pub to network)|

   In addition the initiator evaluates auxv = aux(sec) immediately
   before the ciphertext is transmitted.

4.  Message Format

   The on-wire artifact is unchanged from the base profile.  No
   wire format is defined for aux outputs.

5.  Processing Rules

   On invocation the initiator draws sec and pub, evaluates

      auxv = aux(sec)
      msg  = senc(<sec, pub>, k)

   and transmits msg.  The auxv value MUST NOT be transmitted on
   the wire.  Implementations MAY expose auxv to higher layers;
   implementations that do not expose auxv SHOULD discard the
   value once msg has been transmitted.

6.  Security Considerations

   aux is treated as opaque; the security guarantees of the
   profile do not depend on properties of aux beyond its
   existence.  As aux is never transmitted nor enters any keyed
   computation, observing or controlling its output does not
   weaken the secrecy of sec.
